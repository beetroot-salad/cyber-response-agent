# Phase E — assemble the binding suite (step 8)

## Topology

Three steps; the spine dispatches every one of them, writers included — a single author leaf that spawned its own writers spent an hour of a 2.4-hour phase in sleep loops waiting for them, because only the spine is woken when a background agent finishes.

- **Survey leaf** (Opus, xhigh effort): inputs = `45-dispositions.md`, `70-resolutions.md`, `78-gate-resolutions.md` if any, the spec_graph (demands and ledger — the refuted claims especially), the project profile. Builds the shared machinery every writer needs (fakes, fixtures, helpers) and writes `80-survey.md`: the slice plan — per slice, a name, its demand ids, its test file, the shared machinery it uses. One slice when the suite is small.
- **Writer leaves** (Opus, xhigh effort), one per slice, dispatched by the spine in parallel: inputs = `80-survey.md`, the slice name, and the survey's inputs. Each writes its slice's test file and `82-writer-<slice>.md`.
- **Integrator leaf** (Opus, xhigh effort): inputs = `80-survey.md`, every `82-writer-*.md`, the suite. Applies the writers' requested changes to shared machinery, updates the spec_graph's `discharged_by` pointers, runs the mechanical toolchain over the whole suite, and writes `88-author-digest.md`.
- Dispatch only after §7 has produced `70-resolutions.md`; if the #0 reading flipped there, C's classification re-runs first.

## Charge — every author

Read **references/schema.md** for address forms. The settled assertions are already written, so this is assembly and hardening, not authorship from scratch: turn each disposition into one test, apply the human's rulings exactly (a ruling applied loosely is a fork re-opened silently), and author the situations only the strong author raised. Work with the ledger's refuted claims in hand — you **may not assert content a refutation marks wrong or stale**: pin the demanded correction (red against HEAD is the expected state of a spec), never the ambient string the handoff tells the implementer to change — a test asserting today's refuted behavior is the pinned-green shape, a probed bug hardened into a contract by its own spec.

Build on the project's existing test machinery — a harness that already fakes the dependencies is the starting point, so a new scenario is a few lines of data, not fresh plumbing; the profile's `tests.harness` names it. Then:

- **Induce faults down this hierarchy, never off it.** (1) *Real input through the real primitive, in the test itself* — write the undecodable bytes, create the colliding stem, delete the file: the test re-probes reality on every run, and the taxonomy assumption ceases to exist rather than being pinned once. (2) When the dependency is too expensive or nondeterministic to drive (an LLM, a network), *a fake whose fault content — the exception class, the malformed shape — cites the ledger claim that observed it on the real dependency.* (3) An author-imagined fault is banned: if no claim covers it, request the probe (red-flag it in your digest and stop on that test) rather than inventing: a guard and its test built from the same wrong prior are green together.
- **Declarative fault-injection fakes** — one fake per dependency, driven by a data fault-spec (`fail_on`, `raise_after`, `malformed`, `delay`). The fake injects faults **only** — it never classifies or decides policy. Fakes enter through the entry point's injection seams (a deps parameter, a constructor argument), never by monkey-patching an attribute out from under the target — the profile's `tests.idioms` records what CI enforces here. If the design gives a dependency no seam, the seam is part of the contract — pin it as a demand.
- **Fakes record what they receive.** A payload (`kind: shape`) demand asserts on the *captured inbound payload* against the facet's invariants — the obligation carries the assertion content (rules.md R1) — not on the fake's canned response. A fake that only returns answers leaves the entire outbound channel unpinned.
- **One test per executable demand**, named by the demand's `discharged_by`, driving the **real entry point** against the fakes; assert observable outcomes only — output contents, return value, raised errors, recorded seam calls. This holds for a **census or parity demand** too, and that is where it is usually dropped: enumerating a registry and asserting a structural property of each entry (`isinstance`, `hasattr`, a field is not None) feels like discharge, but a type the production default already satisfies makes the assertion unfailable — it certifies that the *field exists*, never that it is *wired*. If the demand is "every X is connected to Y", drive one X and observe Y's effect; the enumeration is how you pick the subjects, not what you assert about them. `check_binds`' unexercised-seam scan catches the sharpest form, not the whole class. The test's **docstring carries the demand's prose** — the observable outcome and any threaded concept (`salt=deps.salt`) — because that docstring is what `check_binds` scans in place of a demand `outcome`; thread only concepts the demand `binds`, or bind them.
- **Every `kind: negative` demand is paired with its positive control** — on the same address, under the complementary condition (schema.md) — proof the mechanism fired and the observation channel can see the difference. The control takes the shape of the negative: for a redaction, the same bytes *are* returned through the sanctioned path; for a denied action, the allowed variant succeeds; for an absent artifact, the substitute workflow demonstrably completes. And a negative binds **every surface the content could reach** — each of the actor's out-edges (outputs, traces, error messages), not just the obvious one; an unbound surface is exactly where the leak ships. A bare negative passes vacuously (`assert secret not in out` is also green when `out` is empty).

**Run only this suite's files.** Execute the tests you wrote (plus a harness file you changed; a writer runs only its own file) — never the project's full suite: CI runs it, it overruns the shell's time limit, and on a shared box it holds the test lock other sessions wait on; the profile's `gate.notes` carry how this box runs pytest. Run in the foreground: a background run polled from a sleep loop spends the same minutes and hides the output.

**Run the mechanical toolchain before you return** (the integrator over the whole suite; a writer over its own file where a command takes one) — the `spec-graph` commands phase F's mechanical-gate leaf runs (verify.md, "Charge — the mechanical-gate leaf"), `nullstub` included. Each finding is yours to fix while the suite is still in your hands: a test that fails to bind, reach the target, or discriminate under the null stub is an authoring defect, and handed to phase F it costs a repair round and a re-verify. Fix what is test-level; a finding that needs a judgment call (a demand that looks wrong, a claim you cannot cite) goes under `## Red flags`, never settled by weakening the test. The mechanical-gate leaf still runs after you, independently — aim for it to find nothing to repair.

## Charge — the survey leaf

Survey the project's existing test machinery — the profile's `tests.harness` names the starting point — and build what every slice will share: the declarative fakes, the fixtures that stand up the entry point, the helpers. Write them now, once, so writers add scenarios as data instead of each inventing plumbing. Then cut the slice plan: group demands so each slice is one test file a writer can finish without touching another's, keep a negative and its positive control in the same slice, and size slices so none is more than about twice another. Name, per slice, the shared machinery it should use. Digest: slice count, demands per slice, the shared machinery written.

## Charge — a writer

Write your slice's tests and nothing else. Use the shared machinery as the survey wrote it; when you need a change to it, do not edit it — write the change you need under `## Red flags` in your frontier, and work around it locally until the integrator lands it. Digest: tests written, demands discharged, probe requests, shared-machinery requests.

## Charge — the integrator

Apply the writers' shared-machinery requests (reconciling conflicting ones), update every `discharged_by` pointer, and run the suite's files and the mechanical toolchain over the whole suite — the cross-slice findings (a helper two slices both redefined, a fixture one slice broke for another) only appear here. Fix what is test-level; put judgment calls under `## Red flags`. Every settled assertion and every ruling lands in a test or is red-flagged, never silently dropped — check by name against `45-dispositions.md` and `70-resolutions.md`. Digest: tests, demands discharged, probe requests, toolchain status.
