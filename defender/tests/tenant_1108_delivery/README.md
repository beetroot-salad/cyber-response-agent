### Choices where the amendment was silent

1. **Locations.** Exports are exactly `<T>/exports/<commit>/` with the pointer `<T>/exports/current`; drafts are exactly `<T>/drafts/<batch>/agent`. The batch worktree is under the layout's `tenant.worktrees` (`<T>/learning/worktrees`): the amendment's `<T>/worktrees/<batch>` is read as the layout owner's worktree base (D7), not a new folder. *Accepted by the orchestrator at review.* Listings of `exports/` count folders and `current` only, so a lock or other file there is tolerated.
2. **`AgentChange.path`** is repo-relative POSIX (`agent/lessons/x.md`), like revert's lesson path and git pathspecs; `content` is `bytes`, or `None` for a deletion.
3. **Lanes** are declared once per batch, `start_batch(batch_id, lanes=...)`, and govern the box request, derivation and the commit-maker. Lane spellings are not validated by the contract: the amendment deletes the escape checks.
4. **Lock seam.** `tenant_lock(tenant)` is the production context manager the three locked steps use; a busy lock raises `LockBusy` (a `DeliveryRefused`) at once, naming the holder's pid. Probes run in another process, since same-process lock semantics differ by primitive.
5. **Revert (user decision, 2026-10-15).** A revert proceeds only while `main` still holds exactly what the commit-maker wrote for that lesson; then it restores the file to what it was before the agent's change, or deletes it when the agent created it, as one commit-maker commit on `main` with its own branch and PR. If anyone changed the lesson on `main` since (a human edit after the merge), the revert refuses with `DeliveryRefused`: nothing pushed, no PR, `main` unchanged. Other files changing on `main` meanwhile do not stop it. Cases: `test_revert_deletes_a_lesson_the_commit_maker_created`, `test_revert_restores_what_a_lesson_held_before_the_commit_maker_changed_it`, `test_revert_refuses_a_lesson_changed_on_main_since_the_commit_maker_wrote_it` (agent-created and agent-changed). The human merge is simulated as a merge commit (Forgejo's default style); squash and rebase merges, which rewrite the commit-maker's commit, are not pinned. Every other case that reverts (the hook, retry, census and lock cases) now reverts a lesson the commit-maker wrote and a human merged, through `merged_agent_lesson`/`merge_on_remote`.
6. **Staged startup.** The token's file name is not pinned; whether it stays after startup is not pinned. The root-entry check may be the host's own no-follow listing (the fakes answer only `cat`). A draft root holding `settings/` refuses (`settings/` is a run copy's half).
7. **Foreign commits refuse.** Pushing the commit-maker's recorded sha while a foreign commit sits on the branch would also keep it off the remote, but principle 2 asks for the refusal, and the brief names it; the contract requires `DeliveryRefused` before any push. Commit-maker provenance must outlive the delivery object (a later drain delivers the retained branch).
8. **Exact-head lookup stays the paginated listing** (C19). `/pulls/{base}/{head}` is not answered by the fake; using it needs K3's executed result and a contract amendment.
9. **A PR row without a head repository is a `ForgeError`**: excluding it would release the writer lease on unknown evidence. **Pending a user decision** (orchestrator, at review); the case is alone in `test_a_pr_row_without_its_head_repository_is_a_forge_error`.
10. `current_export` refusals are `DeliveryRefused`; `current_export` returns a `TenantExport` (`.commit`, `.path`). It lives in `tenant_delivery` for P3, so P4 must move it (or narrow the dormancy census) before runs import it.
11. `ForgeAddress` has no base path (the design's fields are scheme, host, port, owner, repo), so a forge served under a sub-path is refused.
12. Generic `staged` cases never plant `settings/`: whether a request-lane copy may hold it is left to P4's run copy; only the drain's draft refuses it.
13. **Owner and repository compare without case** (orchestrator decision at review: Forgejo resolves those names case-insensitively). Host compares without case as before. Scheme, port and the path shape are unchanged.
14. **The batch branch is the clone's `refs/heads/<batch.branch>`**, which finish pushes (already pinned by the G2 case, which reads it at the commit-maker's sha). Foreign commits are laid there by plumbing (`plant_raw_commit`), never by `git commit` in the worktree: the design does not fix whether the worktree is attached to the branch. The commit-maker must build on the branch's current tip, or compare-and-swap the ref against its last commit, so a branch moved under it is refused, never overwritten: the sandwich case (`test_a_foreign_commit_beneath_a_later_commit_maker_commit_is_refused`) fails an implementation that force-sets the branch to its new commit and silently drops the foreign one (choice 7: refusal, not silent discard).
15. **A `.git` in a lane** (a `gitdir:` file or a nested repository) is refused at derivation or at commit; either is accepted.
16. **Retried revert.** How a revert retried after a failed PR request ends (success, refusal, error) is not pinned; only that a commit laid on its branch in between never reaches the remote. An implementation that names each revert's branch afresh never meets the laid commit, so for it that case is vacuous; the hook case (choice 17) covers the in-call window where hooks run.
17. **Hooks are not required to run.** The clone-hook revert case asserts a refusal only when its hook fired; an implementation that disables hooks (`core.hooksPath`) must revert normally there.
18. **Fuzzing is a seeded `random.Random`** (four seeds, twelve rounds each, on a base with nested lane folders): `hypothesis` is not a dependency of this tree. Every other round plants one refused entry at a random place, the ten kinds rotated so each is planted at least twice; a replacing link always, and a directory link or FIFO half the time, lands where the worktree holds a file or folder. Some clean rounds commit. A failure names seed, round and the planted entry.

### Not pinned in P3, and why

- **O-B run side** (`RunKnowledge`, the run's settings and stamp from one copy) is P4's; only the export it copies is pinned here.
- **O-D for mid-batch host readers** (typed tools, `open_drain_trees` views, the gates between claims, `stop_and_scrub`) has no P3 caller: those readers are wired onto drafts in P4, which owes the reader census the amendment's security dive names (**the draft-reader census is P4's**, confirmed at review). P3 pins derivation (enumerated and fuzzed) and reset only.
- **"The commit-maker is the only creator of tenant commits"** is pinned behaviourally on all three push routes (a foreign commit is refused on each) and by an executed census at the public boundary: every git process spawned across a drain and a revert is attributed to the public call it ran under. No lexical census of private call sites is asserted (it would pin private names). The census sees git run as a process; an implementation committing in-process (a git library) would escape it.
- **`GIT_TERMINAL_PROMPT=0`** is not separately discriminated: there is no tty under pytest. The post-`open()` rows do drive git onto its prompt path (a helper with no answer); the askpass spies cover `GIT_ASKPASS`, `SSH_ASKPASS` and `core.askPass` there.
- **A retained-route sandwich** (a commit-maker commit on top of a foreign one on a retained branch) is not reachable through the public API: after a failed finish no further claim is made on that batch. The finish-route sandwich and the retained on-top/amended rows stand for it.
- **Choice 5 edges the decision does not settle:** reverting a lesson the commit-maker never wrote (a human-authored one: the literal reading of "only when `main` still holds exactly what the commit-maker wrote" refuses it); a lesson a human edited and then restored to the agent's exact bytes (content or history); a lesson the agent changed in several merged batches (before which change). None is pinned.
- **The publisher** besides a drain is `tenant.py setup`; there is no `tenant.py update` on the base. Only `setup` and the drain's fast-forward advance the clone.
- The device-node row skips without `CAP_MKNOD` (CI runs non-root); the FIFO and socket rows always run.

### Review repair (2026-10-15)

The independent review of `436263b9` returned REVISE. Each finding and what changed (no honest or adversary source was opened for it):

1. **Reset onto a replaced entry.** `_REFUSED_OUTPUT` gains `replace-file-with-link` (a base file replaced by a link to the host folder), `replace-dir-with-link` (a base subdirectory replaced by a directory link) and `replace-file-with-fifo`. The reset is now bounded and must leave every worktree file in the draft as a regular file with the worktree's bytes and the host folder unchanged, so a reset that `copyfile`s onto the box's entry fails (writes through, or blocks). `test_a_claim_reset_resyncs_the_draft_and_never_follows_box_links` gains the same three replacements. `bounded` now releases a FIFO's blocked writer as well as its reader.
2. **Provenance sandwich.** `test_a_foreign_commit_beneath_a_later_commit_maker_commit_is_refused`: claim, a foreign commit laid on the batch branch, claim; the second commit or the finish refuses; no remote branch, no PR. The retained-route sandwich is not reachable (see "Not pinned").
3. **Finish rows** lay their commit with `plant_raw_commit` on the clone's `refs/heads/<batch.branch>` (choice 14), never `git commit` in the worktree.
4. **`.git` in a lane**: `test_git_metadata_in_a_lane_never_becomes_a_commit` (a `gitdir:` file at the lane root naming the tenant clone; a nested repository): refused at derivation or commit, no 160000 entry, HEAD unmoved, worktree and clone clean.
5. **O-E without an answer.** `test_a_credential_file_changed_after_open_never_leads_git_to_prompt` empties or rewrites the file after `open()`; a correct implementation succeeds on what `open()` read, or fails fast, with no spy run. A system-config helper spy (`GIT_CONFIG_SYSTEM`) joins the spies and their positive control. This also covers what the single-read case cannot: its audit hook is in-process and cannot see a helper subprocess re-reading the file.
6. **Lock on every route.** The lock-free case now probes the retained deliver (its PR request; any git it runs) and a revert (its push, its PR request; any fetch) as well as the batch. A busy lock on `start_batch` is asserted to leave no worktree in `git worktree list` as well as none under the worktree base.
7. **Fail-fast bound**: a second taker must answer within 5 s (bounded at 10 s).
8. **Hooks not required.** The hook case is conditional on its marker (choice 17), and `test_a_retried_revert_never_sends_a_commit_laid_on_its_branch` lays its commit by plumbing between two reverts, with no hook (choice 16).

## Local test API seams (implementation choices, not new persisted models)

Shared by the honest implementer and the adversary. All of P3 stays dormant: no production module may name `tenant_delivery` or `TenantDelivery` (census), and P4 wires curators and runs.

**`defender.learning.author.tenant_delivery`** exports:

- `DeliveryRefused(Exception)`; `LockBusy(DeliveryRefused)`, raised at once when the tenant's lock is held elsewhere, its message naming the holder's pid.
- `TenantExport` with `.commit: str` and `.path: Path` (`<T>/exports/<commit>`, holding exactly that commit's `agent/` and `settings/` regular blobs, written from git objects, immutable once published).
- `current_export(tenant) -> TenantExport`: reads `<T>/exports/current` (a pointer file replaced atomically) and spawns no process; an absent, empty or escaping pointer, or one naming a missing export, is `DeliveryRefused`.
- `tenant_lock(tenant)`: the per-tenant file lock under `<T>/` (not `forge/`), a context manager; held only for fast-forward, export publish and worktree creation.
- `AgentChange(path: str, content: bytes | None)`: `path` repo-relative POSIX under `agent/`; `None` deletes. `ChangeSet(changes)`: immutable, built positionally from a sequence of `AgentChange`, iterable. A path outside `agent/`, a traversal or whitespace-led name, `agent/.tenant-id`, `.gitattributes`/`.gitignore`/`.gitmodules` at any depth, or non-bytes content is refused at construction or at commit (`DeliveryRefused`, `ValueError` or `TypeError`).
- `TenantDelivery.open(tenant, *, defender_dir: Path, client: httpx.Client)`: the dormant factory and the single reader of `<T>/forge/git-credentials`. Refusals (O9), origin/credential agreement over the parsed `ForgeAddress`, and protection (A10) as before. No token in `repr`. Methods:
  - `publish() -> TenantExport`: fetch (no lock), then under the lock fast-forward the clone (refusing dirty, untracked or diverged state), refuse any non-blob tree entry under `agent/` or `settings/` and any `agent/.tenant-id` not naming this tenant through `_tenant.parse_tenant_id_bytes`, write the export, replace `current`. Nothing is published on refusal.
  - `start_batch(batch_id, *, lanes: tuple[str, ...]) -> Batch`: publish, then under the lock a worktree of the clone at the export commit under `tenant.worktrees` (host-only, never mounted); then the draft `<T>/drafts/<batch_id>/agent`, a git-free copy.
  - `start_box(request, *, docker) -> BoxExecutor`: the tenant drain's start; never an unsandboxed executor, whatever the operator opt-out.
  - `finish(batch) -> str`: push the batch branch, then the PR found by exact head (forks excluded) or opened against `main`; the PR url.
  - `deliver(batch_id) -> str`: a retained branch (pushed, PR creation failed), by a later delivery object too.
  - `revert(lesson_path: str, lesson_name: str) -> str`: a `ChangeSet` from history (the prior content, or a deletion) through the commit-maker, pushed with its own PR.
  - Every push route first checks that each commit between the base and the branch head is one the commit-maker made, refusing (`DeliveryRefused`, before any push or PR) otherwise. Each route's commits sit on a local branch `refs/heads/<branch>` of the clone before its push.
- `Batch`: `.id`, `.branch` (the branch name), `.export` (`TenantExport`), `.worktree`, `.draft_root` (`<T>/drafts/<batch_id>`), `.lanes`; `.box_request() -> BoxRequest`; `.change_set() -> ChangeSet` (draft against worktree; regular files only, read no-follow, under `READ_LIMIT`; any other entry, an out-of-lane path or a forbidden name refuses the claim whole); `.commit(change_set, message) -> str` (the commit-maker, the only maker of tenant commits: accepts only a `ChangeSet` within the lanes, commits in the worktree with mode 100644, returns the sha); `.reset()` (re-syncs the draft from the worktree without following links).
- Git runs with every credential helper reset and one read-only helper answering only `get` from the tenant file, `GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS=` empty; the clone's own hooks are not disabled (the revert case observes through a `reference-transaction` hook).

**`defender.learning.author.forge`**: `ForgeAddress` (`scheme`, `host`, `port`, `owner`, `repo`; `ForgeAddress.parse(url)`; default port explicit, scheme and host case folded, owner and repository compared without case, `.git` optional; anything but `http(s)://host[:port]/owner/repo[.git]` is a `ForgeError`; equality is the comparison). `ForgejoForge(origin=, token=, client=)` parses once into `.address`, keeps the three-method `Forge` interface plus `verify_main_protection()`, compares every next-page Link's parsed address and repository path against `.address` before requesting it, and counts only rows whose head repository is the base repository (`head.repo.full_name`, with `head.repo_id`, in the observed schema); a row without a head repository is a `ForgeError`. Exact-head lookup is the paginated listing. PR rows normalize to `number/headRefName/url`.

**`defender.runtime.box`**: `BoxRequest.defender_dir` owns code geography (`_render_argv`, `_host_fallback_env`, image resolution). Read-only mounts declare `Mount(..., kind="code"|"data"|"staged")`; writable mounts carry no kind, and a writable `staged` mount is refused. `code` reads back `<code_dir>/<box.CODE_CHECK_FILE>` (`"MOUNT_CHECK"`) inside the one `code` mount; `data` reads its first regular file, empty allowed; `staged` (a host-made copy's root) gets a fresh random token planted at its root for each start, read back as `cat <root>/<token file>`; the root holds `agent/` (a real folder), `settings/` only for a run copy (P4), and that token, and anything else refuses. The tenant drain's start refuses a draft root holding `settings/`. The `agent` kind is retired and refused like any non-kind word. Read-backs compare line-ending-normalized text. Both request-lane entries, `start_box(request, docker=)` and `_lifecycle._start_boxed_request(request, docker)`, are seams. The fakes (`FakeDaemon`, `_Boundary`, `RecordingDocker`, `MountedReadDocker`) answer only `cat <in-box path>` reads (operand last) and the alias probe; any other in-box command answers empty, so a root listing done in the box cannot be judged by them. Drain request: `{(defender_dir, code), (draft_root, staged), (draft_root/agent/<lane>, writable)}`, workdir and `DEFENDER_AGENT_DIR` = `draft_root/agent`.

**Test machinery** (`_support.py`): `build_tenant`/`repo` (local transport behind a network-shaped origin), `http_repo` with `GitHTTP` (real `git http-backend` behind Basic auth, recording `(service, token sent, accepted)` per request; `on_service` fires once per service until `rearm()`), `ForgeHTTP` (`on_request` probe hook), `LockHolder` and `lock_probe` (out-of-process lock holder and taker through `tenant_lock`), `plant_raw_commit` (by plumbing, no hook or worktree; `base=` creates a ref that does not exist yet) and `install_planting_hook` (commits the commit-maker did not make, with its exact message and identities), `merge_on_remote` (a human's merge-commit merge of a PR branch into the remote's `main`) and `merged_agent_lesson` (a lesson written by the commit-maker in its own batch, finished and merged), `plain_file` (a regular file with given bytes, checked without following a link), `bounded` (no hang on FIFOs, reader or writer side).
