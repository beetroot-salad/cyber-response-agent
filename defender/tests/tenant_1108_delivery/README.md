### Choices where the amendment was silent

1. **Locations.** Exports are exactly `<T>/exports/<commit>/` with the pointer `<T>/exports/current`; drafts are exactly `<T>/drafts/<batch>/agent`. The batch worktree is under the layout's `tenant.worktrees` (`<T>/learning/worktrees`): the amendment's `<T>/worktrees/<batch>` is read as the layout owner's worktree base (D7), not a new folder. *Accepted by the orchestrator at review.* Listings of `exports/` count folders and `current` only, so a lock or other file there is tolerated.
2. **`AgentChange.path`** is repo-relative POSIX (`agent/lessons/x.md`), like revert's lesson path and git pathspecs; `content` is `bytes`, or `None` for a deletion.
3. **Lanes** are declared once per batch, `start_batch(batch_id, lanes=...)`, and govern the box request, derivation and the commit-maker. Lane spellings are not validated by the contract: the amendment deletes the escape checks.
4. **Lock seam.** `tenant_lock(tenant)` is the production context manager the three locked steps use; a busy lock raises `LockBusy` (a `DeliveryRefused`) at once, naming the holder's pid. Probes run in another process, since same-process lock semantics differ by primitive.
5. **Revert (user decision, then orchestrator rulings, 2026-10-15).** A revert proceeds only while `main` still holds exactly what the commit-maker wrote for the lesson. The test is content, not history: the change a revert undoes is the most recent commit-maker change to the lesson whose resulting bytes equal `main`'s current bytes (so a human edit later restored to the agent's exact bytes proceeds, and an unmerged change, such as a later batch whose PR is still open or a failed earlier revert, never matches and is skipped without any merge detection); with no such change the revert refuses. It restores the bytes from just before that change, or deletes the lesson when that change created it, as one commit-maker commit on `main` with its own branch and PR. A human edit on `main` since, or a lesson the commit-maker never wrote, refuses with `DeliveryRefused`: nothing pushed, no PR, `main` unchanged. Other files changing on `main` do not stop it. Merge style must not matter: the agent's change is identified from the commit-maker's own commits, not by finding their shas on `main`. Cases: `test_revert_deletes_a_lesson_the_commit_maker_created` and `test_revert_restores_what_a_lesson_held_before_the_commit_maker_changed_it` (each merged by merge commit, squash and rebase), `test_revert_undoes_only_the_latest_of_several_commit_maker_changes` (changed once; changed back to the first bytes, where an earlier change matches too), `test_revert_ignores_a_later_commit_maker_change_whose_pr_is_still_open`, `test_revert_proceeds_when_main_again_holds_exactly_the_agents_bytes`, `test_revert_refuses_a_lesson_changed_on_main_since_the_commit_maker_wrote_it` (agent-created, agent-changed), `test_revert_refuses_a_lesson_the_commit_maker_never_wrote` (the seed, a human-merged lesson), `test_revert_recreates_a_lesson_the_commit_maker_deleted` (orchestrator ruling: a merged commit-maker deletion follows the same rule, `main`'s absent lesson matching that change's result, so the revert recreates the bytes from before it). Across processes: `test_a_later_process_reverts_by_the_commit_maker_record` and `test_a_later_process_refuses_to_revert_a_lesson_changed_on_main` run the revert in a freshly started process (`in_a_later_process`), so the commit-maker's record must outlive the process that wrote it; where it lives is not pinned. Every other case that reverts (hook, retry, census, lock) reverts a lesson the commit-maker wrote and a human merged (`merged_agent_lesson`/`merge_on_remote`).
6. **Staged startup.** The token's file name is not pinned; whether it stays after startup is not pinned, but no earlier start's token may remain beside it (the root holds `agent/`, `settings/` for a run copy, and the current token). The read-back is exact equality. The root-entry check may be the host's own no-follow listing (the fakes answer only `cat`). A draft root holding `settings/` refuses (`settings/` is a run copy's half).
7. **Foreign commits refuse.** Pushing the commit-maker's recorded sha while a foreign commit sits on the branch would also keep it off the remote, but principle 2 asks for the refusal, and the brief names it; the contract requires `DeliveryRefused` before any push. Commit-maker provenance must outlive the delivery object and the process (a later drain delivers the retained branch: `test_a_later_process_delivers_a_retained_branch_by_the_commit_maker_record`, clean and with a commit laid on top, runs that delivery in a freshly started process; the in-process variants stay). Where the record lives is not pinned. *Orchestrator-confirmed at re-review:* the commit-maker refuses when the batch branch has moved from its last own commit and never force-sets over it (fail closed, loudly).
8. **Exact-head lookup stays the paginated listing** (C19). `/pulls/{base}/{head}` is not answered by the fake; using it needs K3's executed result and a contract amendment.
9. **A PR row without a head repository is a `ForgeError`**: excluding it would release the writer lease on unknown evidence. **Pending a user decision** (orchestrator, at review); the case is alone in `test_a_pr_row_without_its_head_repository_is_a_forge_error`.
10. `current_export` refusals are `DeliveryRefused`; `current_export` returns a `TenantExport` (`.commit`, `.path`). It lives in `tenant_delivery` for P3, so P4 must move it (or narrow the dormancy census) before runs import it.
11. `ForgeAddress` has no base path (the design's fields are scheme, host, port, owner, repo), so a forge served under a sub-path is refused.
12. Generic `staged` cases never plant `settings/`: whether a request-lane copy may hold it is left to P4's run copy; only the drain's draft refuses it.
13. **Owner and repository compare without case** (orchestrator decision at review: Forgejo resolves those names case-insensitively). Host compares without case as before. Scheme, port and the path shape are unchanged.
14. **The batch branch is the clone's `refs/heads/<batch.branch>`**, which finish pushes (already pinned by the G2 case, which reads it at the commit-maker's sha). Foreign commits are laid there by plumbing (`plant_raw_commit`), never by `git commit` in the worktree: the design does not fix whether the worktree is attached to the branch. The commit-maker must build on the branch's current tip, or compare-and-swap the ref against its last commit, so a branch moved under it is refused, never overwritten (orchestrator-confirmed, choice 7): the sandwich case (`test_a_foreign_commit_beneath_a_later_commit_maker_commit_is_refused`) fails an implementation that force-sets the branch to its new commit and silently drops the foreign one (choice 7: refusal, not silent discard).
15. **A `.git` in a lane** (a `gitdir:` file or a nested repository) is refused at derivation or at commit; either is accepted.
16. **Retried revert.** How a revert retried after a failed PR request ends (success, refusal, error) is not pinned; only that a commit laid on its branch in between never reaches the remote. Whether the revert's branch survives the failed request is not pinned either. An implementation that names each revert's branch afresh never meets the laid commit, and one that leaves no branch behind gives nothing to lay it on, so for both that case is vacuous; the hook case (choice 17) covers the in-call window where hooks run.
17. **Hooks are not required to run.** The clone-hook revert case asserts a refusal only when its hook fired; an implementation that disables hooks (`core.hooksPath`) must revert normally there.
18. **Fuzzing is a seeded `random.Random`** (four seeds, twelve rounds each, on a base with nested lane folders): `hypothesis` is not a dependency of this tree. Every other round plants one refused entry at a random place, the ten kinds rotated so each is planted at least twice; a replacing link always, and a directory link or FIFO half the time, lands where the worktree holds a file or folder. Some clean rounds commit. A failure names seed, round and the planted entry.

### Not pinned in P3, and why

- **O-B run side** (`RunKnowledge`, the run's settings and stamp from one copy) is P4's; only the export it copies is pinned here.
- **O-D for mid-batch host readers** (typed tools, `open_drain_trees` views, the gates between claims, `stop_and_scrub`) has no P3 caller: those readers are wired onto drafts in P4, which owes the reader census the amendment's security dive names (**the draft-reader census is P4's**, confirmed at review). P3 pins derivation (enumerated and fuzzed) and reset only.
- **"The commit-maker is the only creator of tenant commits"** is pinned behaviourally on all three push routes (a foreign commit is refused on each) and by an executed census at the public boundary: every git process spawned across a drain and a revert is attributed to the public call it ran under. No lexical census of private call sites is asserted (it would pin private names). The census sees git run as a process and requires a commit-making git process under the commit-maker and the revert, so an implementation committing in-process (a git library) would fail it, not escape it; such a design needs the census rewritten.

**`defender.learning.author.tenant_delivery`** exports:

- `TenantExport` with `.commit: str` and `.path: Path` (`<T>/exports/<commit>`, holding exactly that commit's `agent/` and `settings/` regular blobs, written from git objects, immutable once published).
- `current_export(tenant) -> TenantExport`: reads `<T>/exports/current` (a pointer file replaced atomically) and spawns no process; an absent, empty or escaping pointer, or one naming a missing export, is `DeliveryRefused`.
- `tenant_lock(tenant)`: the per-tenant file lock under `<T>/` (not `forge/`), a context manager; a non-blocking try; held for fast-forward, export publish (the export folder and `current` are written while it is held) and worktree creation (the batch's, and any a revert cuts), and never across network I/O (`open()`'s protection read, any fetch or push, a PR request) or a box window.
- `AgentChange(path: str, content: bytes | None)`: `path` repo-relative POSIX under `agent/`; `None` deletes. `ChangeSet(changes)`: immutable, built positionally from a sequence of `AgentChange`, iterable; neither it nor an `AgentChange` lets an attribute be reassigned, and nothing reachable from it is a mutable container. Read-only mounts declare `Mount(..., kind="code"|"data"|"staged")`; writable mounts carry no kind, and a writable `staged` mount is refused. `code` reads back `<code_dir>/<box.CODE_CHECK_FILE>` (`"MOUNT_CHECK"`) inside the one `code` mount; `data` reads its first regular file, empty allowed; `staged` (a host-made copy's root) gets a fresh random token planted at its root for each start, read back as `cat <root>/<token file>` and compared for equality (earlier tokens do not remain); the root holds `agent/` (a real folder), `settings/` only for a run copy (P4), and that token, and anything else refuses. The tenant drain's start refuses a draft root holding `settings/`. The `agent` kind is retired and refused like any non-kind word. Read-backs compare line-ending-normalized text. Both request-lane entries, `start_box(request, docker=)` and `_lifecycle._start_boxed_request(request, docker)`, are seams. The fakes (`FakeDaemon`, `_Boundary`, `RecordingDocker`, `MountedReadDocker`) answer only `cat <in-box path>` reads (operand last) and the alias probe; any other in-box command answers empty, so a root listing done in the box cannot be judged by them. Drain request: `{(defender_dir, code), (draft_root, staged), (draft_root/agent/<lane>, writable)}`, workdir and `DEFENDER_AGENT_DIR` = `draft_root/agent`.
