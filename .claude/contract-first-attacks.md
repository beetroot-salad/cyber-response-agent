# Attack deck

This repo's record of exploit shapes that carried real bugs past a committed suite, for the contract-first plugin's attackers to replay. Append-only.

## 2026-07-21 · PR #678 — a catch-all fault demand discharged at ONE seam; fault the other seams the guarded value crosses
- **violated**: `d7_unmapped_fault_enveloped` — "an unmapped `BaseException` → the fault-class envelope (write a row, never delete one) … never unwinds out of `agent.iter()`" (the pipeline judge's closed-ticket tool, since deleted; `spec_graph_672-closed-ticket-tool.yaml:152`).
- **exploit**: the discharging test injects the fault INSIDE the callee — the verb body, via the fake's `("raise", RuntimeError(...))` outcome — after a clean dependency resolution. Resolve the dependency OUTSIDE the guarded `try` (here `verbs.verbs(SYSTEM)[verb]`, which lazily imports the adapter and can `KeyError`/`ImportError`/`SystemExit`); the resolution fault then unwinds the stage with no row and no breaker record, and the suite stays green because every fake resolves cleanly. Generic replay: for any "any fault of class X → the safe envelope" demand, inject X at EACH seam the guarded value crosses around the `try` — dependency lookup/resolution/import, setup, teardown — not only inside the call.
- **killed by**: resolution moved inside the fault seam (`_run_verb`); a regression test on the recorded-not-unwound property, since deleted with the tool it drove; and — the **mechanical net** — CI gate `tooling/lint/lint_unguarded_verb_dispatch.py`, which deterministically fails a subscripted `registry.verbs(system)[verb]` dispatch resolved outside a fault `try` (modules with a pydantic-ai capability catch-all exempt). The prose replay above is the cross-spec net for the adversarial implementer; the gate is the deterministic in-repo one — belt and suspenders, since a gate is cheap where the replay only shifts the odds.

## 2026-07-21 · PR #677 — a value that makes the gate's own measurement/serialization call RAISE escapes as an exception, not a Decision
- **violated**: the gate's standing fail-closed contract — "every gate that resolves one fails CLOSED instead of propagating" (`investigation/permission/files.py`, RESOLVE_ERRORS) — and D0 (`spec_graph_629-report-output-structure.yaml:49`, "decide_write returns a Decision on any rejection"). D0 is an accept/deny *shape* contract, not a *totality* one: no demand bound the input-processability axis.
- **exploit**: the demand fixed a measurement basis (`_utf8_len = text.encode("utf-8")`), but the suite enumerated only the *valid-but-adversarial* value — multibyte byte-vs-codepoint divergence — never the *un-processable* value that makes the basis call itself throw. A lone surrogate (`"\ud800"`, reachable from a model tool-call JSON arg: `json.loads('"\ud800"')` yields one) makes `.encode()` raise `UnicodeEncodeError` before any Decision is returned; the discharging test fed only ASCII, so it greened on the buggy code. Replays to any serialization/measurement demand: `.encode()`←lone surrogate, `json.dumps`←NaN/inf, `int(...)`←non-numeric str, a parse←malformed bytes — assert the gate returns a fail-closed Decision, never propagates.
- **killed by**: a `try: proposed_text.encode("utf-8") except UnicodeEncodeError: return Decision(False, …)` guard at the artifact dispatch, with a regression that asserts both artifacts return a Decision (never raise) on a lone surrogate.

## 2026-07-23 · PR #700 — trusted prose that DESCRIBES a frame's content stays green while the content moves out of the frame
- **violated**: #680 design, "Behavior change and its cost" — "prose naming sections by bare name … stay valid (C8)" / "the three heading-grammar stages need their prompts reconciled to the new Section names"; inherited rider `spec_graph_672-closed-ticket-tool.yaml:241` — "the rewrite must orphan neither" (never re-bound in spec_graph_680).
- **exploit**: the suite pinned frame SHAPE (tag order, salt, name stability — D19, the R1 gates) and content by SUBSTRING ("findings (1):" anywhere in the prompt; tool names anywhere in the .md), never the coherence of prose ABOUT the content. When a fork resolution (D12, `70-resolutions.md:29`) shrank a frame to data-only ("empty frame for explicit empty content"), every trusted sentence describing what the frame used to carry — a system-prompt cross-reference (benign.md:143 "its key is named there") and an adjacent count header (`{label} (N):` in curator_context) — stayed byte-identical and green while its referent vanished or moved frames. Generic replay: when a spec changes what a payload/section CARRIES, not just how it is delimited, sweep every trusted prose surface (system prompts, harness-authored headers) for claims about that content; implement the content move while leaving each descriptive claim untouched — name-stability and substring pins cannot fail a stale description.
- **killed by**: prose reconciled inline (045ebdcb: benign.md cites the structural refusal; the curator header names the lesson_rows frame) — no discriminating assertion was added, so the replay remains open at the suite level.

## 2026-09-14 · PR #1042 — a "forged/malformed value" demand's own domain-member names the ABSENT case; the discharging test parametrizes only the malformed-but-present cases
- **violated**: demand `r_a_result_event_that_is_forged_or_misplaced` (`spec_graph_1025.yaml:2436-2443`), binding `runs_dir.domain.distinguished[forged-result]` whose own comment reads "string/null/NaN/negative cost or duration" (`spec_graph_1025.yaml:2940`); the same null/missing case is named independently by three lens premises (`30-premises-input-surface.md:175`, `30-premises-dependency.md:57`, `30-premises-author.md:382`).
- **exploit**: the value class a demand's own domain-member (or its premise prose) names as in-scope is broader than what actually landed in the test's parametrize list — a plausible near-miss implementation (`cost is not None` gating instead of `isinstance(cost, (int, float))`) passes every parametrized case and crashes on the untested member (`None`, or the key absent). Generic replay: for every "exercises invalid/forged/malformed X" demand, diff the domain-member's bound comment (and any premise naming the value class) against the discharging test's actual parametrize tuple — a member named in prose but missing from the tuple is the exploit.
- **killed by**: `test_1025_a_result_event_that_is_forged_or_misplaced`'s parametrize widened to include `None`, plus a new `test_1025_a_result_event_with_no_total_cost_usd_key_at_all` for the missing-key case.

## 2026-09-14 · PR #1042 — a page's own escaping/grammar-gate policy is demanded against ONE attacker-writable filename surface and never extended to a structurally identical sibling surface
- **violated**: the design's general rule (`spec_graph_1025.yaml:4029`, fork J5+J11 — "every substituted id/href/heading/class attribute-safe by construction... grammar-gated on `is_valid_run_id`'s alphabet") names "stems" as a governed frame slot (`spec_graph_1025.yaml:4083`); the author lens ties a label to "a trace stem" as a hostile-input surface (`30-premises-author.md:433`).
- **exploit**: the demand ledger minted a `hostile-stem` member + demand for only ONE filename-derived id surface the policy covers (`world_archive`, discharged by `test_1025_a_gather_summary_stem_that_is_hostile`); a second attacker-writable surface built the same way (`wire_logs/questioner_<stem>_trace.jsonl`) has no `hostile-stem` member and no discharging test. An implementation that routes the first surface through the grammar gate and the second through plain `html.escape` alone (safe by luck, not by policy) ships with zero discriminating coverage there. Generic replay: when a design states one policy over a CLASS of surfaces, enumerate every concrete construction site in code before minting demands — closing the fork on the first surface found leaves every sibling surface untested.
- **killed by**: `test_1025_a_hostile_wire_logs_trace_stem`, pinning today's `esc()`-only defense on the `tx-` id.

## 2026-09-14 · PR #1042 — a CLI's `if __name__ == "__main__"` line is invisible to every test that drives the entry point in-process; a same-shaped subprocess test for an unrelated reason does not substitute
- **violated**: brief premise F14 (`10-brief.md:136` — "the module imports in the working order and `python visualize_episode.py <dir>` runs standalone"), never converted into an executed demand.
- **exploit**: every CLI test drives `main(argv)` in-process, or where it does shell out for an unrelated reason (a `PYTHONHASHSEED` determinism check), does so via `python -c "<code calling render_episode directly>"` — never `python <script> <args>`. Neither path executes the literal `__main__` guard line, so a hardcoded `main([])` (a plausible copy-paste-from-a-smoke-test mistake) ships silently. Generic replay: for any script with a `__main__` guard, confirm at least one demand invokes the actual file as a subprocess with real positional arguments — an in-process call or a `-c`-driven subprocess both leave the guard line permanently dark.
- **killed by**: a real subprocess invocation of the script file with real arguments — today `test_1025_the_standalone_script_runs_with_no_pythonpath_from_any_cwd`, into which the original main-guard test was folded (it ran the same invocation, less strictly).

## 2026-09-20 · PR #1090 — a "must not false-positive on real vocabulary" demand's discriminating test names only the design doc's own example words, which happen to avoid the naive implementation's actual blind spot
- **violated**: issue #401's design doc, O6/M7 — "The scanner must also be discriminating: real inventory vocabulary … must never trip it, or every audit becomes noise." A test existed for exactly this (`test_real_inventory_vocabulary_does_not_trip_the_scanner`, checking `canary-1`/`event.outcome: failure`/an `Accepted publickey` line).
- **exploit**: a marker-scan implemented as a plain substring check (`marker in text.lower()`) passes every fixture the discriminating test names, because none of those fixtures happen to contain a marker as a pure substring of an unrelated word. The actual collision — "default" contains "fault", "evaluate"/"medieval" contain "eval" — was never in the test's vocabulary sample, because the sample was drawn from the design doc's own named examples, not from an adversarial search over the marker list itself. Generic replay: for any "discriminating against real values" demand where the values are drawn from the design doc's own prose examples, construct at least one fixture by taking each forbidden marker/pattern and finding an unrelated real word that contains it as a substring — the design's own examples are exactly the ones an implementer already thought to handle.
- **killed by**: `test_ordinary_words_containing_a_marker_as_a_substring_do_not_trip_it` (`chaos/tests/test_o6_audit.py`), plus switching the scanner from substring to exact-token matching over letter-run tokens (`chaos/audit.py`) — chosen over a `\b`-boundary regex because `\b` treats `_` as a word character and would miss a compound key like `defender_eval`, one of the suite's own already-passing positive cases.
- **since superseded**: the word scan no longer gates the audit at all. The second review of #1090 showed the token list itself false-positives on real syslog (`general protection fault`, `/usr/bin/eval`) — no discriminating fixture can fix a check that looks for words when the ledger knows exactly what was written. The gating check is now ledger-driven (`chaos/audit.py::audit_payloads` takes the records and looks for controller processor bodies and ingest errors naming controller-touched fields); `scan_markers` survives as an advisory tier and the test above still pins it. Generic lesson: when a "must not false-positive" demand keeps needing new fixtures, the check is probably lexical where it should be structural.

## 2026-11-01 · PR #1350 — a catch that maps a whole exception family to one meaning ("any DB error = lost lock") is tested only with the one cause the design named
- **violated**: DC-14 "An exception inside a step becomes the tenant's failure; the loop goes on", against RC-1 "any error on the lock connection … no failure is recorded"; `test_a_failure_text_the_database_cannot_store_is_still_recorded_and_the_pass_goes_on` (test_atk1_pg_lock.py).

Generic replay: for each handler that maps an exception family to one outcome, enumerate the family's causes (connection, fence, data, constraint) and inject each through every write that crosses the handler, on the real backend — an in-memory twin that raises a different class cannot see it.
