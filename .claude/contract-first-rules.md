# contract-first rules

Rules agents wrote for this project, each removing a cause behind several cache entries; written by the contract-first `maintain-cache` skill, reviewed by the human at merge.

- R1 | A local green proves nothing about a service-gated test: before trusting one, read the service markers in `defender/pyproject.toml`'s `[tool.pytest.ini_options] markers` (each names the env vars it needs and says it skips without them locally and fails without them in CI), and for each marker the change reaches either supply the service or treat that marker's tests as not run, checking the skip count rather than the failure count. | why: service-backed tests (`postgres`, `openbao`) skip silently locally and fail only in CI, so each new service was rediscovered as an unexpected CI red or an unearned local pass | src: #1342, #1384
- R2 | Before hand-off, every changed test that drives a planted or published tenant has run its own setup and preconditions up to its own assertions. When the contract changes what base tenant loading requires (`tenancy/_tenants.REQUIRED_SETTINGS`, `records/_alert_input.FACT_KEYS`, the committed `knowledge/tenant-fixture`), run those tests (through `defender-pytest`) under an uncommitted pytest plugin, kept in the run's working record, that patches only those loading facts over base; a red that stops at base acceptance (`TenantRefused`, `AlertMappingFault`) is stopped early, not evidence about the test | why: the committed fixture ships ahead of the base product, so every run.main or published-tenant test stops at acceptance and defects in its setup (planting-helper semantics, acceptance rules in front of the leg) stay hidden until the code stage; #1359's RC-1, RC-2 and RC3-2 surfaced only through a reviewer's probes and `sim1359.py`-style plugin | src: #1359
- R3 | CI's `test` job (`.github/workflows/ci.yml`) is the reference environment, and this host is not it: before reading a local red, skip or pass as evidence, check whether the job's own setup (the user it runs as, the runtimes it installs and registers, the services it starts) would change it; a result that hinges on such a difference is "not run here", neither a regression nor a pass. R1 is this rule's application to service markers | why: tests that hinge on host privileges (root skips unreadable-file arms) or on installed runtimes (gVisor `runsc`) were each rediscovered as a mystery red or an unearned green; worktree-only reds (no `.venv`, no mypy, no docker mount, dev Forgejo state) were rediscovered again in #1391 | src: #1359, #1375, #1391
- R4 | CI's `lint` job (`.github/workflows/ci.yml`) is the lint reference, and this repo has no local mirror of it: before hand-off, run each of its gates the change can reach (ruff twice, mypy, vulture, the lint tool tests and the other `tooling/lint/` gates), from the repo root with `/workspace/defender/.venv`, copying the commands from the job's `run:` steps rather than from memory; a local `ruff check --select E,F` is not the lint gate | why: the job's gates beyond E,F ruff (C901 at complexity 10, the extended ruff families, mypy and its venv-only config, the vulture ratchet) were each rediscovered one run at a time, as a CI red or a late lint red after the change looked done | src: #1342, #1343, #1412
- R5 | A worker on this host (an attacker, a repair author, a verifier) runs on a root account shared with other sessions and behind a test-slot queue: its brief states the hazards and the budget up front: destructive file moves are `rm`, never `mv` to `/dev/null`; processes are stopped by the PID it started, never by a `pkill -f` pattern; slot waits run 10 to 70 minutes, so it is told how many confirming runs it has and that each exploit's kill is confirmed on its own (or the stack's result is attributed per exploit), not once for a stack. Cost: a longer brief and one more run per exploit. | why: the same shared-host, slow-queue conditions produced the `/dev/null` replacement, a `pkill` that could kill another session's run and attackers stacking exploits in one confirming run, and earlier runs rediscovered the slot waits | src: #1377, #1385, #1412
- R6 | A contract test for a module drives the real module and fakes only at its process or network edge (docker or shell calls, the cluster's HTTP): a hand-written stand-in for the module itself is not allowed in a test rig, because nothing checks it against the real interface and the fidelity review and the attackers (who mutate the real code) both pass over it. A fake at the edge answers as the real tool does, including failure codes and states (curl's exit code on a refused connection, `false` with rc 0 for a stopped container). Cost: the edge fake is bigger and needs its own tests (`test_1347_rig_docker.py`). | why: the lab-layer stand-in hid a signature mismatch, swallowed curl exit codes and a stopped container read as running, all shipped past review and attack | src: #1347
- R7 | A simulated shell, docker or store fake never silently accepts input it does not model: it records it as `unmodelled` and the rig asserts that list is empty, so an unmodelled form fails the test loudly instead of skipping the path. A fake that exists to expose a race interleaves at every read made outside the lock as well as at writes, and models the lock primitive (`flock`) itself, so a non-atomic release cannot pass. Cost: each new shell form the code uses needs modelling before its tests run. | why: one unmodelled `$(...)` silently skipped a path in 252 tests, and a lenient fake let a non-atomic lock release pass | src: #1347
- R8 | A confinement check over a language another system owns (ES|QL, SQL, a shell) allow-lists what it can read exactly as the owner does and refuses everything else: it never denies a known-bad list, and any form it cannot read with certainty (an unknown command, a quoting it might lex differently) is refused, not skipped. The check says how it fails when the owner's grammar moves. Cost: some valid queries are refused until a reviewed change adds the form with a test. | why: a hand-written lexer plus deny-list failed open twice in #1347, once on a quoting disagreement and once on an unknown command, and the second turned an agent's in-pattern query into a setup fault that marked elastic down | src: #1347
- R9 | A test of "the lock is checked between steps" takes the lock at every real gap the code has between steps, not only inside a step: each sleep, delay, repeat boundary and between-change point of the fake seams, in separate cases, each with a control that holds the token and runs on. A fake that acts only inside the step satisfies a check placed anywhere. Cost: one parametrised case per gap. | why: a re-check placed after a step and before its pause passed every test because the fake took the lock inside the step; the gap was a second place the same check had to hold (runner steps, runner repeats, `activate` changes) | src: #1347
- R10 | A guard that protects a destructive recovery step (a pre-restore check, a reuse check) must run before the step and must itself be bounded: every wait in it has a named limit much shorter than the step it guards and a stated outcome on timeout (replace, not wait or refuse), and every path that reaches the same wait (the pre-check and the reuse path) gets the same bound. Test each such guard with a wedged and a will-not-start input and assert the elapsed time. Cost: a timeout constant and two fault cases per guard. | why: the A2 UUID refusal ordered after the discard escaped review, and its fix then waited up to an hour on a wedged node that the restore was meant to replace, on two paths; both are one guard whose order and whose bound were each unchecked | src: #1347
- R11 | A fake of an external system (Elasticsearch, a container image, a host's volumes) is written from behaviour observed on the real system, not from the design's assumptions: before the contract is committed, probe the real system for each behaviour the code under test relies on (what it refuses, what it names, what it lacks, how it orders, what it counts), record the version and the observed request and response, and list anything not observed as unobserved so a live check covers it. A green suite over unprobed fakes proves only that code and fake agree. Cost: one short read-only probe session per new fake behaviour, and a fake revision when the probe disagrees. | why: the r6.4 fakes modelled none of the live behaviours below, so a green suite hid three live failures (backing-index write refusal, missing pipelines on restore, stream membership by name), plus `_doc` paging, the missing `flock`, ancestor patterns and a live-volume tar | src: #1347
