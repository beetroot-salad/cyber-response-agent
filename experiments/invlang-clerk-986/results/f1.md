- **Per-turn output halves-to-thirds and the 10k+-token turns vanish.** Every A run has a
  turn of 10–11.5k output tokens — the row-authoring turns. C's biggest turn is 2.4–4k. The
  content MAIN pushes through tools (prose in C, prose+rows in A) is the same order of
  magnitude; what disappeared is thinking spent on the grammar. The pre-measurement had
  attributed all of MAIN's thinking to the investigation; ~2/3 of it was the format.
- **Gather is lead count, not per-lead cost.** A's two expensive runs ran 11 leads
  (140–160 gather calls); C-t4 ran 128 calls for a comparable $0.66. A: 8.5 leads/run, C:
  6.5. Four runs each is inside the spread — the smoke run alone had $0.59 of gather.
  Whether MAIN plans fewer leads with less in front of it is a real question this n cannot
  settle.
- **Cost, honestly stated.** Whole-run $ is 18% lower in C. Of that, MAIN's own drop is
  $0.26 and the clerk costs $0.27 back — so on MAIN+clerk alone the arms are level
  ($0.44 vs $0.43), and the headline saving is the gather difference. The clerk *does* pay
  for itself; it does not (yet) net a saving on the part of the run it touches.

## Quality on this fixture

- C closed `benign` 3/4 and `false-positive` once; A closed benign 2/4, `inconclusive` once,
  and **`malicious` once** — on a container startup script. No C run closed malicious.
  A-t3's verdict rests on "root SSH from external IP 147.235.199.7 ten seconds before the
  burst" — the operator's own SSH session into the VPS during the lever-up that restarted
  the container (the earlier `b986-t6` found the same story). A fixture caveat, not an arm
  effect: both arms investigate the same world, and only A took the bait, once in four.
- C-t3's `false-positive` names a real detection defect: the rule groups by `host.name`,
  which is always the Docker host for Falco events, and a baseline lead (l-006) found
  identical bursts on 08-18 and 08-22. That is the rule-logic reading `defender/SKILL.md`
  asks for at ORIENT, and it is arguably the best close any run reached on this alert.
- The clerk's give-ups (5 across the 4 runs, of 27 calls) were dominated by one mechanical
  pattern — a resolution row naming two owning leads — see `mid.md`. Three of the four C runs
  still produced a document that validates with zero findings at close; all four closed.
- `false-positive` (C-t3) requires a detection-logic defect in `detection_notes`; the
  validator admitted it. Whether the defect claim is fair is the judge's question.
